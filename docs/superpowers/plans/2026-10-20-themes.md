# Theme System Implementation Plan

**Status:** in-progress
**Date:** 2026-10-20

## Goal

Replace the current two-axis system (Theme=light/dark × Accent=green/blue/purple/orange) with a single-palette model: 6 complete palettes (zinc, forest, ocean, violet, sunset, mono), each with light+dark variants, selected via `data-theme="palette"` + `data-mode="system|light|dark"`.

## Non-goals

- No Rust backend behavior change (settings persist as JSON; only the key name changes)
- No new UI components beyond the palette picker tiles
- No animation on theme switch (instant swap)

## Files to change

### 1. `apps/web/src/styles/app.css` — restructure
- Remove the old `:root[data-theme="light"]` block
- Keep `:root` as zinc-light fallback (current dark tokens become zinc defaults; current light tokens become the zinc light variant under `data-mode="dark"`)
- Keep all `.dark`, sharper, and utility rules unchanged
- Add `@import "./themes.css";` at top

### 2. `apps/web/src/styles/themes.css` — new
```css
@import "./themes/zinc.css";
@import "./themes/forest.css";
@import "./themes/ocean.css";
@import "./themes/violet.css";
@import "./themes/sunset.css";
@import "./themes/mono.css";
```

### 3. `apps/web/src/styles/themes/zinc.css` — new
- `[data-theme="zinc"]` — current light tokens (light variant)
- `[data-theme="zinc"][data-mode="dark"]` — current dark tokens
- `@theme inline` mapping (same as current)

### 4. `apps/web/src/styles/themes/forest.css` — new
- Green accent on dark + light surfaces
- `[data-theme="forest"]` light variant + `[data-theme="forest"][data-mode="dark"]` dark variant

### 5. `apps/web/src/styles/themes/ocean.css` — new
- Blue accent (#6086e3 base)
- Light + dark variants

### 6. `apps/web/src/styles/themes/violet.css` — new
- Purple accent (#b07cf0 base)
- Light + dark variants

### 7. `apps/web/src/styles/themes/sunset.css` — new
- Orange accent (#e5995c base)
- Light + dark variants

### 8. `apps/web/src/styles/themes/mono.css` — new
- True grayscale (0 chroma everywhere)
- Light + dark variants

### 9. `apps/web/src/lib/settings.ts` — refactor
- Replace `Theme` type with `Palette` and `Mode` types
- Replace `Accent`/`ACCENTS`/`ACCENT_ORDER` with `PALETTES: Record<Palette, { label: string; colors: string[] }>`
- Update `DEFAULT_SETTINGS`: `palette: "zinc"`, `mode: "system"`
- Rewrite `applyAppearance()`:
  - `root.dataset.theme = settings.palette`
  - `root.dataset.mode = settings.mode` (or remove for "system")
  - Keep shape + sizeMode
  - Remove inline accent var setting
- Export `migrateSettings(old: any): Settings` mapping `accent` → `palette`, `theme` → `mode`

### 10. `apps/web/src/hooks/useSettings.tsx` — update
- No signature change; works with new types automatically

### 11. Settings Appearance UI — update
- Find the current theme+accent picker (likely in a settings page component)
- Replace accent swatches with palette tiles (name + color dots)
- Replace theme radio with mode segmented control (System / Light / Dark)

### 12. `crates/aevio-core/src/settings/mod.rs` — Rust migration
- Add `Palette` enum (Zinc, Forest, Ocean, Violet, Sunset, Mono)
- Keep `Accent` enum but deprecate
- `Settings` struct: replace `accent: Accent` with `palette: Palette`
- Migration: old `"accent":"green"` → `palette: Forest`, etc.
- `appearance_init_script`: seed `aevio.theme` (palette name) + `aevio.mode` (light/dark/system) + `aevio.shape`

### 13. `apps/web/index.html` — update pre-paint script
- Read `aevio.theme` + `aevio.mode` + `aevio.shape` from localStorage
- Set `data-theme`, `data-mode`, `data-shape` on `<html>`

## Validation

1. `bun run fix` passes
2. `bun run verify` passes (oxlint + oxfmt + tsc + cargo fmt + cargo clippy)
3. `cargo test --manifest-path apps/api` — Rust settings tests pass
4. `node --test scripts/*.test.mjs` — frontend tests pass
5. Manual: `bun run dev:screenshot` — palette picker works, mode toggle works, all palettes render correctly

## Execution order

1. CSS themes (files 1-8) — pure CSS, no JS dependency
2. Settings lib + migration (file 9) — foundation for UI
3. Rust migration (file 12) — independent of frontend
4. Settings UI (file 11) — depends on lib
5. Pre-paint script (file 13) — last, after JS is stable
6. Validate (all checks)
